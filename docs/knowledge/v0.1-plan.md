## Owner steps (not code)

- **Switch the live site to Drizzle (step 6):**
  1. Supabase dashboard → **Connect** → **Transaction pooler** → copy the URI (port 6543) and put your database password in it. (Forgot it? Project Settings → Database → Reset database password.)
  2. Add it to `.env.local` as `DATABASE_URL=…`, then check on the Mac: `pnpm content check --store postgres` should list the three guides.
  3. Vercel → Settings → Environment Variables (Production): add `DATABASE_URL` (mark it **Sensitive**) and change `CONTENT_STORE` to `postgres`. Redeploy.
  4. `/api/health` should say `"store":"postgres"`. Save something in the live editor. If anything is wrong, set `CONTENT_STORE` back to `supabase` and redeploy.
- Push `b6d5863` from the Mac (docs only; it isn't on GitHub). Pull with `--rebase` first: `main` has moved on.
- Run `SUPABASE_CONTRACT_TESTS=1 pnpm test supabase` on the Mac: the delete (step 4) is only tested against local files from a cloud session.
- Add the `SUPABASE_SERVICE_ROLE_KEY` secret in GitHub (CI then checks stored guides).
- An uptime monitor on `/api/health`.
- A backup routine for the database (`pnpm content pull` on a schedule).
- Decide whether to scrub `takenAt` from old `hike_revisions` rows (12 of 15 rows hold it on 2026-10-08) and from git history.
- Run the live checks that remain after step 11.
